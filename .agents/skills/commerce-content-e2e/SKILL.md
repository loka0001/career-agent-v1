# Commerce Content E2E

## Purpose

Produce PASS/FAIL evidence for product-backed generation, factual validation, merchant edit,
approval, durable publication, and persisted result state.

## When To Use

- After changes to Content Studio UI/API, generation, product validation, approvals, publishing,
  job handlers, idempotency, or external-operation reconciliation.
- Before claiming the local content journey is release-ready.

## When Not To Use

- Do not publish against a real provider unless the operator explicitly authorizes that acceptance
  stage.
- Do not describe demo/fake publication as Facebook or Instagram acceptance.

## Inputs

- A disposable checkout initialized and running through `commerce-clean-bootstrap`.
- API on port 8000, Vite on 5173, and the independent worker running and ready.
- The one-time password generated by the same checkout.

## Workflow

1. Confirm the seeded product catalog and all three local processes are healthy.
2. Run the committed browser journey:

   ```powershell
   $env:UI_DEMO_PASSWORD = Read-Host "One-time local demo password"
   npm --prefix web run verify:journeys
   Remove-Item Env:UI_DEMO_PASSWORD
   ```

3. Interpret only the Content Studio portion as this skill's result. It must create exactly one
   draft from a real product, show factual validation, persist a merchant edit, approve the edited
   snapshot, enqueue publication, and observe the same item reach `published`.
4. Confirm approval actor/time/hash and publication audit evidence refer to the approved revision.
   If the outbound result is uncertain, require the reconciliation state; never retry blindly.
5. After a fix, run focused regressions:

   ```powershell
   uv run pytest tests/api/test_content_studio.py tests/integration/test_external_operations.py tests/integration/test_application_flows.py -q
   ```

## Expected Output

- Exactly one new draft is created from a persisted product.
- Generated claims match authoritative product facts.
- The merchant edit is saved before approval.
- Approval evidence is immutable and tied to the published revision.
- The independent worker reaches one persisted published result with no browser/network errors.

## Failure Conditions

- Invented product facts, silent replacement of the merchant edit, or approval of a different
  revision.
- Publication before explicit approval, duplicate publication, blind retry after unknown provider
  outcome, or status shown as published without persisted result evidence.
- Demo publication represented as credentialed provider acceptance.

## Verification

- Record candidate identity, command, date, exit code, draft delta, content ID, approval state, job
  result, and final status without credentials or sensitive provider payloads.
- Real Meta acceptance remains a separate owner-authorized workflow.
