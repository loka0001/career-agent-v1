# Route capability matrix

Last audited: 2026-08-08

Legend:

- **Real** — backed by the current store-scoped API.
- **Provider** — internal state is real; the external action requires configured credentials.
- **Demo** — available only when the server explicitly enables demo mode and visibly labelled.
- **Internal** — authenticated operational functionality that does not require an external provider.

All authenticated routes use the current `AuthContext` cookie session. Mutations use the
CSRF cookie/header contract. Operator visibility is server-derived.

## Navigation outcome

Primary navigation contains Command Center, Inbox, Content Studio, Products, Integrations, and
Store Settings. Orders, Opportunities, Customers, campaign tools, analytics, automations, team,
security, privacy, API/Website, Billing, and operator tools remain available through the More tools
disclosure, mobile drawer, command palette, or direct routes as authorized. Billing is not shown
while free access is active.

## Completion rules

A route is marked complete when its source and API tests cover its meaningful, empty,
error, and mutation states and the route-wide browser audit reaches it without runtime,
network, naming, or overflow errors. Public entry and the critical Command/Orders shell
are additionally checked at 390×844, 768×1024, and 1440×900; shared responsive
navigation and styling apply to secondary routes. Arabic RTL and English LTR are
verified through persisted locale switching and route headings.
Provider-dependent actions must remain disabled with a setup path or return a mapped
actionable error. The final browser evidence is produced by
`web/scripts/verify-ui.mjs`.
